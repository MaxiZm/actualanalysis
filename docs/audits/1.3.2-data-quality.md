# GPT-5.5 / Pro and scoring input audit — 2026-09-05

The reported 0.8-point Mixed gap was not evidence that GPT-5.5 was better. From the actual accepted 1.3.1 paired posterior draws, P(Pro > base) was 44.6%, with a 90% difference interval of −15.0 to +11.9 points. Agentic already favored Pro at its median, 59.95 versus 58.82. These are unresolved comparisons, not reliable ordinal differences.

`posterior-audit.py` reproduces every number from the accepted run without refitting; `posterior-audit.json` contains the output. `correct-records.ts` reproduces the corrected input and row-by-row SHA-256 removal manifest.

## Verified data bugs fixed

1. **Different FrontierMath revisions were pooled.** OpenAI's April 23 GPT-5.5 launch figures concern the old questions: 51.7/52.4% on Tiers 1–3 and 35.4/39.6% on Tier 4. Epoch released v2 on June 12, correcting 42% of problems. Its original run CSV identifies both the new and the old tasks explicitly. Twelve pre-v2 vendor observations had incorrectly been assigned v2 benchmark IDs. They were removed from the manual input and preserved in `removed-pre-v2-manual.json`. The old Tier-4-2025-07-01 alias was also removed from the v2 registry.
2. **Wrong subset counts and invented successes.** Registry counts 295/43 described all questions, including 10/2 public examples. The private sets contain 285/41. GPT-5.5's Tier 4 run evaluated 40 items (mean .725, SE .0714995); treating it as a guessed 31/43 was not valid. Original reported SE is now retained, so no guessed success count is required.
3. **Epoch aggregate discarded the reasoning setting and original uncertainty.** Its ECI CSV stores a model-level best score; the original `/data/benchmarks.csv` has exact model version, run ID, start time, task revision and SE. The new original-run parser selects the latest completed run per exact configuration and revision, never the maximum score. Default Epoch ingestion uses these records for both v2 FrontierMath sets. Source IDs and origin provenance are explicitly independent for these Epoch-run evaluations.
4. **Pro was incorrectly treated as fixed effort.** OpenAI's current model documentation specifies medium/high/xhigh, with high default. `gpt-5.5-pro.yaml` now records high/xhigh standard/maximum and reasoning controls. Previously high and xhigh ARC observations were pooled in one fixed-effort system.
5. **Duplicate fallbacks entered the joint fit.** The 1.3.1 fit used `mapped` rather than the provenance-selected result set. The existing lineage gate only helps when lineage IDs exist. The final correction manifest removes 295 verified lineage copies after checking effort, benchmark/grader revision, tools and unique origin identity. Manual display rounding is allowed; ambiguous mirrors and genuinely different configurations are preserved. Exact Epoch runs now carry source run lineage IDs.

## Why the old domain estimates differ

All four Pro fitted benchmarks chiefly measure reasoning. Pro has zero direct agentic, code and communication cells; HLE contributes only a small knowledge loading. The Mixed five-domain estimate necessarily infers those missing domains through a prior/covariance model. The paired domain differences Pro−base were agentic +2.90, code −3.26, reasoning +0.83, knowledge −4.29, communication +0.72. Code's learned correlation with reasoning was only .247, and essentially zero with communication. The model cannot infer a universal cross-domain gain just from the four reasoning-heavy tests.

Sparse evidence should widen uncertainty; the UI should describe the ordering as a median estimate and show the paired unresolved comparison. Do not enforce Pro > base by model name or use the lower uncertainty bound as the central score.

## Recommended integration and checks

- Use `corrected-records.json` as the previous-input base, then append new model coverage. Rerun `correct-records.ts` after model aliases finish to resolve additional original Epoch runs.
- Stable upstream lineage is now implemented for ARC mirrors, including ECI entries with null origin URLs only when an official ARC configuration uniquely matches. The old base85% Epoch mirror had no effort metadata and erroneously became a standard-effort observation even though the origin is xhigh; it is now counted once with that native observation.
- Do not globally choose only the highest provenance per model/benchmark; that could discard valid different configurations. Deduplicate by source observation identity/configuration before likelihood construction.
- Refit corrected data before changing priors. Correct effort metadata is a required fix independent of ranking direction.
- A future parent-linked signed trait deviation is defensible only for verified computational variants. Use a generic explicit registry relation, a zero-centered/signed learned deviation and enough residual variance; never a forced positive effect. Validate with leave-one-variant-out prediction, proper log scoring and 90% interval coverage across several Pro/non-Pro pairs before adopting it. Current corrected data must not be used to tune until this one pair sorts in the desired order.
- Audit SimpleQA metric identity separately: its current registry notes say F1, while the likelihood treats it as counted accuracy; this was not changed during this bounded task.
- DeepSWE's existing fit flags its discrimination as unidentified, so a precise difficulty/slope headline is inappropriate. Its reported calibrated slope is only .399, with substantial cell misfit; observations are not expected to all lie exactly on a single regression line.

## Permanent follow-up implementation

- `harmonizeObservationLineages` is called after ingestion annotations; `selectLineageObservations` supplies one preferred native/latest observation per verified lineage to the joint fit. The method preserves independent replications and different configurations.
- Same-configuration deduplication now uses the latest source timestamp even if rows arrive in reverse chronological order; it never uses maximum score.
- Database supersession now links only verified lineage copies, not every lower-provenance configuration.
- Each accepted joint run stores `current_evidence_observation_keys`. Current snapshot export filters against this exact reviewed input inventory. Old v1 records and duplicate captures remain in the database/history, but cannot reappear as current rows merely because they share a fitted model/benchmark cell.
- Final input: 4547 original records −459 rejected/replaced records +128 exact Epoch records =4216. The 459 removals are 12 v1 vendor results, 152 lossy ECI FrontierMath aggregates and 295 verified lineage copies.

Validation performed: root, ingestion and DB typechecks passed; 50 focused ingestion/pipeline/database tests passed, plus the earlier 20 adapter tests. New regressions cover exact run identity/SE, revision/public-subset exclusion, ambiguous/equal-score effort configurations, independent replications, latest-not-best selection and historical-row exclusion from current exports. Scoring Python, index config, stored database rows and published snapshot files were not changed by this audit; export/persistence code was changed for the next accepted publication.
